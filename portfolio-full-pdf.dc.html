Study 1 · OCR-LLM 기반 판매논리 자동 생성

2개 모듈·4개 서브모듈로 구성된 자동화 파이프라인.

텍스트 추출 모듈

  • 전처리 — Histogram Equalization·CLAHE로 명암 대비를 높여 텍스트 가독성 개선. CLAHE 적용 OCR이 원본보다 낮은 평균 CER을 보임
  • 검출·분할 — CRAFT로 텍스트 위치 검출 후, 글자가 잘리지 않는 좌표에서 이미지 분할, 분할 이미지별 OCR 실행 후 원래 순서로 병합. 핵심은 단순 일정 크기 분할이 아니라 텍스트 검출 위치 기준의 분할
  • OCR — EasyOCR(검출 CRAFT, 인식 CRNN), CPU Only 환경에서 실험

LCORE — LLM 기반 문맥적 OCR 정제

LCORE(LLM-based Contextual OCR Refinement)는 OCR 결과를 상품의 품목·상품명·문맥 기준으로 정제하는 단계입니다.

  • 입력: OCR 텍스트·상품 품목·상품명
  • 맞춤법 수정, 문맥 불일치 문장 수정·삭제, 상품 문맥 기반 오류 복원
  • 제공된 정보 범위를 벗어난 새 사실 생성은 방지

동일한 검색 파이프라인에서 문서 표현 방식만 바꿔 비교 — Baseline(상품 속성만) vs Proposed(상품 속성 + FABEC·구매동기). 목적은 정답 상품을 찾는지가 아니라 사용자 의도에 더 적합한 상품을 상위에 배치하는지 검증.

직수량 추정 모델 — 설계 아이디어

기본 아이디어 — 직수는 저울로 재기 전엔 정답을 알 수 없지만, 유축은 배출량을 실측할 수 있다는 점에서 출발. 좌·우 유방을 각각 "얼마나 차 있는가(충만도)"라는 0~1 사이의 상태로 표현하고, 이 상태가 시간에 따라 어떻게 줄고 차오르는지를 두 가지 함수 관계로 모델링.

  • ① 회복은 지수적으로 목표치에 다가가는 관계 — 유축·수유 직후엔 빠르게 다시 차오르다가, 시간이 지날수록 차오르는 속도가 점점 느려져 최대치에 수렴. "완전히 빈 상태에서 얼마나 걸려야 다시 차는가"를 나타내는 개인화된 시간상수를 두고, 직전에 유난히 많이 비웠을 때는 회복이 일시적으로 더 더뎌지도록 보정
  • ② 추출은 한계체감(diminishing returns) 관계 — 수유·유축 초반에 대부분의 양이 나오고, 시간이 길어질수록 추가로 나오는 양은 점점 감소. 이 역시 시간상수로 표현해, 수유 시간이 예측량에 미치는 영향이 앞부분에 몰리도록 구성
  • 최종 예측량 — 현재 충만도 × 개인별 용량(최근 유축량 상위권 실적으로 추정) × 이번 수유 시간의 추출 정도를 곱한 값에, 아기가 유축기 대비 실제로 얼마나 잘 빨아 먹는지를 나타내는 효율 계수를 반영. 이 효율 계수는 저울로 잰 직수 기록이 쌓일 때마다 예측치·실측치를 비교해 점진 갱신되어, 보수적인 기본값에서 출발해 사람마다 다른 수유 패턴에 스스로 맞춰감
  • 주관·수동 보정 — 저울 없이도 "팽팽함/보통/부드러움" 입력이나 "적었어요/많았어요" 버튼으로 상태를 보정, 직전 유축과의 시간 간격에 따라 보정 폭을 다르게 반영(방금 많이 비운 직후는 크게, 안정 상태는 작게)
  • 단계적 폴백 — 정답 라벨이 없는 문제이므로, 데이터가 충분한 사용자에게는 좌우 분리 모델을, 데이터가 적은 초기 사용자에게는 단순 평균 모델로 자동 전환해 완벽한 정확도보다 "합리적으로 쓸 만한 안내"를 목표로 반복 튜닝

AI에게 바로 구현을 맡기지 않고, Andrej Karpathy·Matt Pocock류의 바이브코딩 워크플로우를 참고해 "무엇을 왜 만드는지"를 먼저 텍스트로 굳히는 단계를 거쳤습니다. 아이디어를 던지면 AI가 허점과 전제를 되물어 정리시키는 grill-me 단계 → 그렇게 다듬어진 내용을 실행 가능한 이슈 단위로 쪼개는 to_issue 단계 → 이슈를 다시 배경·요구사항·수용기준을 갖춘 PRD로 정리하는 to_prd 단계를 거쳐야 코드 생성으로 넘어가도록 워크플로우를 잡았습니다.

이 단계를 거치면 AI가 애매한 요구를 임의로 해석해 엉뚱한 코드를 만드는 일이 줄고, 직수량 추정 모델처럼 사양이 복잡한 기능에서도 구현 전에 로직의 허점을 먼저 걸러낼 수 있었습니다.
