sLLM 파인튜닝 기반 고객 문의유형 분류 모델 (PoC)

문제 정의, 모델 설계·개발, 현업 커뮤니케이션 — 분류 체계 재설계를 제안하고 PoC 단계에서 종료

배경

  • 상담 STT(Speech-to-Text) 텍스트에서 고객 문의유형을 자동 분류하는 과제
  • 기존 Sentence-BERT 기반 모델이 운영되고 있었으나 정확도가 낮았고, 원인은 모델보다 학습 데이터에 있었음
  • 진단 결과 라벨 부족·미라벨 유형·극단적 불균형의 세 문제가 겹쳐 있는 상태
문제 상세
라벨 부족전체 수백만 건 가운데 라벨링 비용 제약으로 약 2만 건만 수작업 라벨 확보
미라벨 유형 다수105개 문의유형 중 약 30개는 정답 데이터가 전무
극단적 불균형상위 10개 유형(상품문의 등)이 80% 이상을 차지, 실운영 예측 결과도 30~40개 유형에 집중

접근

1. 모델 선정 및 파인튜닝

  • 한국어 특화 모델 Bllossom(Llama3.1 8B 기반)을 LoRA로 파인튜닝
  • 단순 분류 헤드 대신 Triplet Loss를 적용해 유형 간 임베딩 분리도를 높이는 방향으로 학습
  • 유형 수가 많고 표본이 적은 조건에서 클래스 경계를 확보하는 것이 목표
LoRA Triplet Loss Llama3.1 (Bllossom)

2. 폐쇄망 환경에서의 자동 라벨링

  • 라벨 부족을 LLM 자동 라벨링으로 보완하려 했으나, 보안 정책상 외부 LLM API 사용 불가
  • 당시 막 공개된 Reasoning 계열 DeepSeek 12B를 사내 온프레미스로 구동해 미라벨 데이터 자동 라벨링 파이프라인 구축
DeepSeek On-premise LLM Auto-labeling

결과 및 판단

  • 자동 라벨링으로 학습 데이터를 크게 늘렸으나, 표본 10건 미만 유형이 여전히 다수 남음
  • 모델링 기법만으로는 해결할 수 없는 수준이라고 판단
  • 추가 튜닝보다 105개 유형 체계 자체의 재설계가 선행되어야 한다고 현업에 제안
  • 현업은 건수가 적은 유형을 잡아내는 것이 업무상 중요하다는 입장으로, 우선순위가 조율되지 않아 PoC 단계에서 종료
회고
  • 폐쇄망 제약 안에서 오픈소스 sLLM 파인튜닝과 LLM 기반 라벨 보강을 끝까지 실행해본 프로젝트
  • 데이터 문제로 보였던 것이 실제로는 문제 정의(분류 체계 설계) 단계의 문제였음을 확인
  • 표본 10건짜리 유형을 신뢰성 있게 분류하는 것은 통계적으로 성립하기 어려움 — 필요한 것은 더 좋은 모델이 아니라 유형 체계의 재정의

기술 스택
